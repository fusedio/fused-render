Markdown v2

One template that reads, writes, links and graphs .md — replacing templates/markdown/. Read/write behaviour follows Obsidian.

Today markdown/template.html does one thing: marked.parse(await fused.readFile(file)) into a div. No editing, no [[wikilinks]], no backlinks, no graph. This describes the replacement — the same view, plus an editor and a link layer, plus a folder-level graph built from the same index.

Status — what was built (2026-07-28), and how it diverged from this plan. Everything below shipped, with one deliberate change of shape: the template is one Live Preview surface, not three view modes. The Reading/Source switcher described further down was built and then removed, and with it marked, the whole rendered-HTML pipeline, the view param and ⌘E. The persistent toolbar is gone too; backlinks moved off a footer into a right sidebar shared with the graph, behind one small toggle. code is untouched and still registered for .md. The contract is SPEC.md §32 (MD-1..MD-22); the decisions are D153..D159.

Follow-ups since (D159). The decoration set is a StateField, not a ViewPlugin — CM refuses a plugin-provided replacement that spans a line break, and the table widget does, so scrolling a note containing a table threw mid-update and left unpainted regions on screen. There is a read-only/editing mode after all (MD-1a), but only as the two CM facets the unwritable-file path already used, in the edit param, with no second pipeline and no change of appearance: the reading view is still "these decorations over a locked buffer". The note view's scan root now climbs to a vault marker rather than being the note's own folder (see Scope, below). On a path with no scan — a mount, a refusal, a failure — wikilinks render inert rather than as ghosts, because "we never looked" is not "it is not there" (MD-11a). The side panel is resizable, the graph layout is about twice as open and fits itself to the canvas, and both palettes are now Obsidian's own neutral scale with fused's accent kept for links.

Why one surface rather than copying Obsidian's split: in Obsidian, Reading and Editing are leaves of a single MarkdownView, so ⌘E keeps the editor instance — and with it the caret and the undo history. Here a mode is a template swap, so the same toggle costs more and buys less. A read-only file gives the reading view for free: identical decorations over a locked buffer.

Deliberately not built, each recorded in MD-18b/MD-12 rather than left implied: the frontmatter properties table (the block is dimmed instead); inline note embeds (an embedded note renders as a link — no second parse, no recursion); inline markup inside a table cell, which a decoration cannot reach because it cannot span into a widget's DOM; paste or drop an image, because fused.writeFile takes UTF-8 text only and a binary attachment write needs a runtime change first; .fused-graph.json tuning and gitignore-awareness of the walk; sticky default-mode settings (view state is in fused.params, which is shareable but not sticky); and step 5's watch-registry subscription — see the two divergences below.

Three surfaces, one template

Note view .md

A Live Preview editor: always editable, markup rendered in place, resolved [[wikilinks]], no mode switcher. The default mode for .md.

Local graph .md

Neighborhood of the open note — BFS to depth N. In the right sidebar under the backlinks, toggled, depth in the URL.

Vault graph /

Every note under the current folder. A directory template, registered next to _listing and preview.

Registry changes are small:

".md":       ["markdown", "code", "reader", "annotate"]   // markdown now = read+write+links
"/":         ["_listing", "graph", "preview", "zarr_aoi"] // new folder mode, gated

The folder mode gets a condition.py (SPEC CT-12) so it only offers itself where a notes vault is — as built, where index.md exists (Index.md probed alongside it, for a case-sensitive filesystem), since telling "this is a vault" from anything else needs the listing this rule forbids. The first cut probed a wider list of "entry-point" notes (README.md, Home.md, notes.md, …) and that was wrong in one direction that matters: README.md is in essentially every code repository, so the mode was offered on every checkout on the disk. The remaining cost is one-directional and is discoverability, not capability: a vault with no index.md is not offered the mode, while _mode=graph still reaches it by hand and the local graph panel in the note view is untouched. That gate must never list or walk the directory — same rule zarr_aoi/condition.py documents. Cheap bounded probes only (two os.path.isfile checks), fail closed.

Reading and writing — Obsidian parity

Read/write behaviour follows Obsidian explicitly. That is a reachable target rather than an aspiration, because Obsidian's editor is CodeMirror 6 — and templates/vendor/codemirror.bundle.js is CodeMirror 6, built from scripts/vendor-codemirror/entry.js, with Decoration/StateField/StateEffect/RangeSet already exported for annotate mode. Live Preview is a decoration set over a CM6 document, not a WYSIWYG DOM; the mechanism we already ship is the mechanism Obsidian uses.

One view mode — as built; see the status note above

Live Preview only. An editable CM6 document where markup is replaced by rendered widgets — except on the lines the selection touches, where the raw source is revealed so it can be edited. Headings size up with # hidden; bold/italic/strike/inline-code lose their markers and keep their styling; code fences keep their markers and gain the embedded language's highlighting; blockquotes, bullets, rules, pipe tables, images, links, wikilinks, embeds, ghosts and tags all render.

What a range is comes from syntaxTree, so no block parser is duplicated in JS. Wikilinks and tags are not in the grammar, so they are matched by regex and then checked against the tree — which is where MD-3's code-masking rule holds on this side.

InteractionBehaviour
Click a linkFollows it — the widget is opaque, so the caret does not land in it.
Click an image, table or tagPuts the caret inside: the source appears, which is how the content is edited.
Click a checkboxToggles and writes back. It stays a control even under the caret, as in Obsidian.
Read-only fileSame decorations over a locked buffer — this is the reading view.
Read-only modeThe identical mechanism, asked for by the user (MD-1a): the same two facets, the same decorations. With no caret nothing reveals, so the note reads as fully rendered. An unwritable file cannot be toggled out of it.

Frontmatter is the one place the grammar cannot be trusted: it has no frontmatter rule, and ---\ntitle: x\n--- parses as a HorizontalRule followed by a SetextHeading2, so YAML rendered as a rule plus a large heading. The block is found by a line scan, dimmed, and every tree decoration inside it suppressed.

Because this layer's correctness lives entirely in what the grammar calls each range, it is covered by running it: scripts/vendor-codemirror/live-preview-probe.mjs executes the real builder against the real grammar headlessly, and tests/test_markdown_live_preview.py asserts over the decoration set it produces. Two real bugs — the frontmatter case above, and Link/Image nodes wrapping wikilink brackets, which silently rendered no wikilinks — were found that way after the source read correctly.

Saving — Obsidian's model, not ours

Obsidian has no save button, no dirty indicator, and no save prompt. It autosaves on an idle timer (~2 s), on focus loss, on switching file or tab, and on quit; ⌘S merely forces the flush early. We adopt exactly that through fused.writeFile(file, text). Dropping our own dirty-dot/save-button idea is the point — the absence of save ceremony is the behaviour being copied.

One deliberate deviation: conflicts. Obsidian assumes it is the only writer in the vault — a clean buffer silently reloads when the file changes on disk, and otherwise the editor's copy wins. fused-render sits on shared and mount-backed paths where that assumption doesn't hold. So: clean buffer → silent reload, exactly as Obsidian. Dirty buffer and mtime moved → a banner offering reload-or-keep, instead of last-write-wins. Everything else about saving is unchanged.

Two more places Obsidian has nothing to copy, because it has no mount layer:

  • Read-only detection reads the shell's persisted read_only flag, not os.access. On an rclone mount with CacheMode=full a doomed write succeeds locally and only 403s later on async upload — so the editor opens disabled rather than apologising afterwards.
  • Watch-driven reload was the plan for the silent-reload-when-clean rule. As built it is event-driven instead: the view calls fused.autoReload(false) and re-stats on focus / visibility change, plus at the next save through the expectedMtime lock. A stat ticker was rejected outright — polling is exactly the traffic that killed a mount in the fs/events stat-storm incident, and branching on mount-ness inside the template would break the rule that templates stay mount-agnostic. The cost is that an external change is noticed a moment later rather than instantly; the rule itself (clean → silent reload, dirty → banner) is unchanged. This also stands in for step 5 of the order of work.

Editing behaviours to match

These are what make Obsidian feel like Obsidian, and each is a small CM6 keymap or input handler:

  • Smart lists — Enter continues - , 1. , - [ ] and renumbers; Enter on an empty item ends the list; Tab/⇧Tab indent and outdent list items.
  • Auto-continue blockquotes (> ) and auto-pair brackets, quotes and backticks; typing a pair character with a selection wraps it.
  • Formatting keys — ⌘B bold, ⌘I italic, ⌘K link, ⌘⏎ toggle checkbox. All toggles, so pressing again unwraps.
  • Paste a URL over a selection → [selection](url).
  • Paste or drop an image → write the file via fused.writeFile and insert ![[name.png]]. Obsidian's attachment-location setting (vault root / same folder / a named subfolder) maps onto .fused-graph.json; default is same folder.
  • Cursor and scroll position remembered per file; undo history per open tab.
  • Frontmatter renders as a properties table in Live Preview, raw in Source.

Link authoring

The autocomplete popup is the feature that makes wikilinks usable, so it's part of read/write rather than part of the graph:

  • [[ → fuzzy list of notes · [[# → headings in this note · [[note# → headings in that note · ![[ → embeds · # → tags. ⏎/Tab accepts, Esc dismisses.
  • Candidates come from the index — the same rows the graph reads, so the popup is free once the index exists.
  • New link format matches Obsidian's setting: shortest path when possible / relative / absolute — and defaults to shortest, consistent with resolution.
  • Use [[Wikilinks]] toggle: off means new links are inserted as ordinary markdown links with relative paths. Both forms are always read.
  • Clicking an unresolved link creates the note — Obsidian's behaviour, and only possible because this template writes.

Two Obsidian behaviours are explicitly out of the template's reach and belong to the shell: rename updates inbound links (needs a hook on the explorer's rename, plus a multi-file write), and vault-wide search / quick-switcher. Worth doing, later, elsewhere.

Vendoring additions

One rebuild of scripts/vendor-codemirror/ with these added to entry.js: @codemirror/lang-markdown (with GFM), WidgetType, ViewPlugin, MatchDecorator, keymap from @codemirror/view; EditorSelection, RangeSetBuilder from @codemirror/state; syntaxTree from @codemirror/language; autocompletion from @codemirror/autocomplete. Anything not re-exported gets tree-shaken, per the note in that file.

The write path is what makes the graph live. Each autosave re-parses exactly that note, updates one index row, and re-assembles the graph in memory. That's the whole incremental story — no rebuild — and it's also how the [[ popup stays current.

Links

Parsed from the source before marked sees it, so both surfaces agree on what a link is:

SyntaxMeaning
[[Note]]Link, resolved by name
[[Note|label]]Link with display text
[[Note#Heading]]Link to a heading anchor
![[image.png]]Embed — resolved through fused.rawUrl()
#tagTag node (outside code fences)
](./rel.md)Ordinary markdown links count as edges too

Resolution: shortest path that's unambiguous. As built, the tiers are tried longest-context-first — sibling folder, then vault root, then path suffix, then bare basename, case-insensitively with the extension optional — and a tie at any tier resolves to nothing rather than to the nearest file, which is where this deliberately differs from Obsidian: picking one of two Design.mds would make the graph assert an edge the author never wrote. Unresolved targets become dim ghost nodes in the graph and dashed links in the text — clicking one offers to create the file, which is only possible because this template can write.

Resolve at read time, never at index time. Renaming Foo.md silently changes what every other note's [[Foo]] points at. So the index stores raw link targets and resolution happens during assembly. Caching resolved edges is the one mistake that makes incremental updates wrong instead of merely slow.

The index

Nothing is recomputed from scratch on open. Three tiers:

Where it lives: ~/.fused-render/graph/<sha256 of realpath(root)>.sqlite — under home_dir(), so FUSED_RENDER_HOME overrides work, and resolved on each call like USER_TEMPLATES_DIR. Home dir rather than an in-folder sidecar: no repo pollution, nothing to gitignore. The absolute root path is stored inside the DB so a moved folder or hash collision is detectable.

Cost profile:

  • Cold — one walk plus N small reads (skip files over ~256 KB; they're not notes).
  • Warm — one stat-only walk plus reads for changed files, typically zero.
  • Deletions — free: assembly only uses rows whose path appeared in the current walk.
  • Parser change — bump parser_version to invalidate everything at once.

Scope: the folder for the folder graph, a vault marker for a note

The folder graph is scoped by the folder you're standing in. That matches the explorer (you're always in a directory), needs no setup, and mirrors Obsidian's vault. An index file as the primary mechanism would need manual creation, go stale on the next new note, and restate what the links already say.

What folder scope alone doesn't answer is which folder — and for the note view the answer "the note's own folder" turned out to be wrong, not merely imprecise. It was what shipped first, and on a vault where docs/note.md links ../spec/overview.md it meant: both links ghosted, backlinks empty, one note in the graph. Every link leaving the folder looked broken and every link arriving from outside it was invisible.

So the default now climbs from the note's directory to the nearest ancestor carrying a vault-root marker — .obsidian/, .fused-graph.json, or .git (a directory in a clone, a file in a worktree, so both are probed) — and falls back to the note's own directory when there is none. Never $HOME, never /. An explicit root param still wins. Three properties make the climb safe rather than merely convenient: it is bounded (8 levels, and the filesystem root ends it anyway); it never enumerates — fixed isdir/isfile probes per level, the same CT-12 rule as the folder gate, and doubly binding here because the ascent is choosing the scope of a walk; and it never enters a mount-backed path, so a local note living under a mounted folder is scanned where it is instead of being answered mount_unsupported. A failed mount import means "cannot tell", which reads as "do not climb".

A wider root makes the truncated cap matter more, not less, so the "only the first N notes were scanned" notice stays surfaced in the sidebar. .fused-graph.json counts as a marker but its contents are still unread: the tuning it was designed to carry (root override, include/exclude globs, colour groups, default depth) remains unbuilt, as does gitignore-awareness of the walk.

Mounts: out of scope for the graph

The recursive walk is the expensive part, and a recursive walk over a remote mount is precisely the shape that wedges it (kernel NFS listing on a flat million-key prefix). Rather than bound that risk, the graph simply does not support remote mount paths at all:

  • The folder mode's gate returns False for any mount-backed path, so the graph is never offered there.
  • graph.py refuses a mount-backed root outright — a clear "not supported on remote mounts" result, never a partial walk. Belt and braces: the gate is the UX, this is the guarantee.
  • No walk of any kind touches a mount path, so the wedge is structurally impossible rather than merely unlikely.
  • Hard caps still apply on local roots (file count, per-file bytes), and dropped files are reported rather than silently truncated.

Reading and writing a single .md file on a mount stays fully supported — that's one bounded read and one bounded write, which is what every template already does. Relative markdown links still navigate, because the page resolves those against the note's own folder and needs no scan for it. Only the recursive graph is local-only.

And a refused scan must not be reported as an answer. This was got wrong first time round and is worth stating: with no scan the page holds no resolution map, and it rendered every wikilink as a dim ghost titled "Unresolved — click to create this note". That asserts the target doesn't exist when nothing ever looked — and offers to create a note that may be sitting right beside the open one. Three states, not two: scanned and unresolved is a ghost (dashed, click-to-create); not scanned is inert — no ghost styling, no create-on-click, and a title saying targets aren't resolved here. The sidebar does the same thing rather than hiding an empty backlinks list, because an empty list also reads as an answer, and it says it in graph.py's own words so a mount refusal, a note outside its root and a crashed scan each read as themselves.

Rendering the graph

As built: hand-rolled, and shared. The sim and every interaction rule live in templates/shared/graph-canvas.js, served from the existing /template-shared/ mount and driven by both graph surfaces — extracted the moment the second one appeared, so they cannot drift into two versions. Nothing was vendored. The original choice was open: either vendor d3-force (~15 KB) or hand-roll an O(n²) sim; both are fine to ~1500 nodes on a Canvas 2D surface. Behaviour worth copying from Obsidian: node radius ∝ degree, labels fading past a zoom threshold, hover highlighting the neighbourhood, drag-to-pin, ghost nodes dimmed, and the settling layout fitted to the canvas. Clicking a node navigates to that note. Graph state — depth, filters, focus — goes through fused.params, so a graph view is URL-shareable, which Obsidian's isn't. (The panel width deliberately does not: that is a personal preference, so it lives in localStorage, and a shared link should not carry someone else's window furniture.)

Spacing is set for the label, not the node — a label is drawn above its node, and an 11px one is 60–100px wide, so the original ~80px equilibrium put every label on top of its neighbour. Roughly doubled. It is not scaled per surface: once the layout is fitted to the canvas, scaling it uniformly changes nothing on screen, so what differs between a 320px sidebar and a full window is the zoom. Two bounds keep the folder surface honest, where the same sim can be handed hundreds of notes — nodes seeded on a disc sized to the node count rather than all on one small ring, and a per-step speed ceiling, without which the first few frames threw a 600-note graph several thousand pixels apart and it cooled before it could recover. All of that was measured by running the sim headlessly and counting label collisions at the resulting zoom, not judged by eye.

Order of work

  1. Link layer in the existing template. Parse [[…]], resolve, render a backlinks footer. Small, useful on its own, and it forces the resolution semantics to be settled before anything depends on them.
  2. Editing, Obsidian-style. Rebuild the CM6 bundle with the markdown grammar, then Source mode → Obsidian's autosave/reload semantics → the editor keymap and input handlers → Live Preview decorations last, since it's the largest piece and everything else works without it. At this point markdown supersedes code for notes.
  3. The index. graph.py — walk, parse, cache rows, assemble on request. Reachable from the template via fused.runPython().
  4. The graph views. Local panel first (bounded, no walk beyond depth N), then the folder-level mode with its gate. Local paths only — mount-backed roots are refused, per above.
  5. Live updates. Subscribe the root to the existing watch registry; re-parse one file per change.

Steps 1–2 ship the read/write replacement. Steps 3–5 add the graph on top of an index the editor is already maintaining.
